# SAP 용어 — 풀어 쓰는 법

> Skill `ko-terms` 의 참조 파일이다. chat · 트로브 두 레포지토리가 함께 쓴다. SAP 쪽 뜻만 적는다 — 각 프로젝트가 정한 것(chat 은 접속 이름을 열쇠로 쓴다 등)은 `chat-terms.md` · `trove-terms.md` 에 있다.
> 칸: **용어 · 풀이(현장에서 부르는 말 포함) · 쓰는 법(예) · 출처**.
> 출처 «일반 SAP 지식」 인 행은 2026-11-27 chat 쪽에서 처음 채운 것이다. **트로브 쪽에서 SAP 실물(트로브 tool 결과 · SAP help)로 확인하고 고친다** — 확인하면 출처 칸을 «트로브 확인(날짜)」 으로 바꾼다.
> SAP 이름 · 값은 **원문 그대로** 적는다(대소문자 · 앞자리 0 · 앞쪽 공백을 바꾸지 않는다 — 두 레포지토리 CLAUDE.md GR55).

## A. 시스템 · 접속

| 용어 | 풀이 | 쓰는 법(예) | 출처 |
|---|---|---|---|
| 고객사 SAP 시스템 | 한 고객사의 SAP 시스템 하나와 **그 시스템에만 있는 사실**(객체 · 소스 · 데이터 · 설정 · 커스텀 · 사용 현황) | «고객사 SAP 시스템의 `ZSD_ORDER` 소스」 — 표준 설명과 다를 수 있는 사실을 말할 때 | chat CLAUDE.md 0-5-2 |
| 일반 SAP 지식 | 어느 고객사에도 같은 **SAP 표준의 지식**(표준 문서 · SAP help · 표준 객체 · 트랜잭션 설명 · 베스트 프랙티스) | «일반 SAP 지식으로는 VBAK 에 이 필드가 있다(이 고객사 시스템에 있는지는 따로 확인)」 | chat CLAUDE.md 0-5-2 |
| SAP 접속 · 접속 이름 | 고객사 SAP 시스템 하나로 가는 **접속**과 그 이름(예 `ACME-PRD-100`). SID · client · host · port 는 그 접속의 속성이다 | «접속 `ACME-PRD-100` 에서 조회」 — SID 만으로 시스템을 가리키지 않는다 | chat CLAUDE.md 0-5-2 · U62 |
| SID · client | **SID** = SAP 시스템 ID(세 글자 — 예 `PRD`) · **client** = 한 시스템 안의 업무 단위 번호(세 자리 — 예 `100`). 고객사끼리 겹칠 수 있다 | «SID `PRD` · client `100`」 — 원문 그대로 · 앞자리 0 을 지우지 않는다 | chat CLAUDE.md 0-5-2 · GR55 |
| 시스템 랜드스케이프 · DEV · QAS · PRD | 개발 → 품질(시험) → 운영으로 이어지는 시스템 묶음. 바뀐 객체는 TR 로 차례로 옮긴다 | «DEV 에서 만들고 QAS 에서 확인한 뒤 PRD 로 이송」 | 일반 SAP 지식 |
| 트랜잭션 코드(T-code) | 화면 하나로 들어가는 코드(예 `SE11` · `VA01`). 현장에서 «티코드」 | «T-code `VA01`」 — DB 의 «트랜잭션」 과 헷갈리면 «T-code」 로 쓴다 | 일반 SAP 지식 |

## B. 개발 객체 · 이송

| 용어 | 풀이 | 쓰는 법(예) | 출처 |
|---|---|---|---|
| 객체 유형 · 하위유형 | SAP 객체의 종류(ADT 기준 — 예 `TABL` 테이블 · `PROG` 프로그램 · `CLAS` 클래스)와 그 안의 세부 종류(예 `TABL/DT` 투명 테이블). `유형/하위유형` 모양으로 함께 쓴다 | «`TABL/DT` 인 `ZSD_HEAD`」 — 트로브가 돌려준 값을 바꾸지 않고 그대로 넘긴다 | chat CLAUDE.md CR3 |
| skeleton / full | SAP 객체 응답의 노드 표식 — **skeleton** = 이름만 있는 자리표시 노드 / **full** = 내용까지 채워진 노드. skeleton 이 «없는 객체」 라는 뜻은 아니다 | «skeleton 노드라 내용은 아직 없다(없는 객체가 아니다)」 | chat CLAUDE.md 0-5-2 · CR3 |
| 고객 객체 · 이름 공간 · CBO | 고객이 만든 객체. 이름이 `Z` · `Y` 로 시작하거나 등록한 이름 공간(`/ABC/…`) 안에 있다. 한국 현장에서는 고객 개발 객체를 «CBO」 라고 부른다 | «CBO 프로그램 `ZSDR0010`」 · 이름 공간이 든 이름은 `/ABC/CL_ORDER` 처럼 그대로 | 일반 SAP 지식 · chat 역설계 설계서 §0 |
| 패키지(DEVC) | 개발 객체를 묶는 단위(옛 이름 «개발 클래스」). `$TMP` 는 로컬 패키지라 이송하지 않는다 | «패키지 `ZSD_MAIN` 의 객체」 | 일반 SAP 지식 |
| TR(트랜스포트 요청) | 바뀐 객체 · 설정을 다음 시스템으로 옮기는 묶음. 현장에서 «TR」 · «트랜스포트」. 워크벤치 요청(개발 객체)과 커스터마이징 요청(설정)이 있다 | «TR `DEVK900123` 에 넣는다」 | 일반 SAP 지식 |
| ADT | ABAP Development Tools — Eclipse 의 ABAP 개발 도구와 그것이 쓰는 SAP REST API(`/sap/bc/adt/…`) | «ADT 로 소스를 읽는다」 | 일반 SAP 지식 · chat CLAUDE.md CR8 |
| 활성화 · 활성 버전 | ABAP 객체는 저장만 하면 **비활성 버전**이고, 활성화해야 실행에 쓰인다 | «저장했지만 아직 활성화하지 않았다」 | 일반 SAP 지식 |
| 응용 컴포넌트 · 모듈 | 패키지 · 객체가 속한 업무 영역(예 `FI-GL`) · 그 첫 마디(`FI` · `CO` · `SD` · `MM` · `PP`) | «응용 컴포넌트 `SD-SLS`」 | 일반 SAP 지식 · chat 역설계 설계서 §0 |

## C. 데이터 사전(DDIC)

| 용어 | 풀이 | 쓰는 법(예) | 출처 |
|---|---|---|---|
| 투명 테이블 · 구조 · 테이블 유형 | DB 에 실제로 있는 테이블(`TABL/DT`) · DB 에 없고 모양만 정한 것(`TABL/DS`) · 내부 테이블의 모양(`TTYP`) | «구조 `BAPIRET2` 는 DB 테이블이 아니다」 | 일반 SAP 지식 |
| 데이터 요소 · 도메인 | **데이터 요소** = 필드의 뜻(라벨 · 검색 도움말 · 문서)이고 현장에서 «데이터 엘리먼트」 / **도메인** = 기술 형식(유형 · 길이 · 고정값 · 값 테이블) | «데이터 요소 `KUNNR` · 도메인 `KUNNR`」 | 일반 SAP 지식 |
| 고정값 · 값 테이블 | 도메인에 적어 둔 허용 값 목록 · 허용 값을 담은 테이블 | «도메인 고정값 `A`(활성) · `B`(차단)」 | 일반 SAP 지식 |
| 검색 도움말(search help) | 필드 입력 때 F4 로 뜨는 값 찾기 화면. 현장에서 «서치 헬프」 | «검색 도움말 `DEBI`」 | 일반 SAP 지식 |
| 전달 클래스 | 테이블이 무엇을 담는지 정한 표시 — `A` 응용 데이터 · `C` 고객 설정 · `L` 임시 데이터 · `G` · `E` · `S` · `W` 는 그 밖의 시스템 · 설정용 | «전달 클래스 `C` 라 커스터마이징 테이블이다」 | 일반 SAP 지식 |
| 유지보수 뷰 · SM30 | 테이블 내용을 화면에서 고치게 만든 뷰와 그 T-code | «`ZSD_CFG` 는 SM30 으로 관리」 | 일반 SAP 지식 |
| CHAR 빈 값 · 공백 | SAP 은 `''` · `' '` · `IS INITIAL` 을 같게 본다. **뒤쪽 공백은 없는 것**으로 보고 **앞쪽 공백은 값의 일부**다. 대소문자를 가린다 | SAP 으로 가는 SQL 의 빈 값은 `' '` | 두 레포지토리 CLAUDE.md GR55 |
| NUMC | 숫자만 담는 **문자** 유형. 앞자리 0 을 포함한 원문이 값이다 | «`0001` 을 `1` 로 바꾸지 않는다」 | GR55 |
| DATS · TIMS | 날짜 `YYYYMMDD` · 시각 `HHMMSS` 를 담는 문자 유형. 빈 날짜는 `00000000` | 화면에서 빈 날짜는 빈칸으로 보인다 | GR55 |
| CURR · QUAN | 금액 · 수량 유형. **참조 필드**(통화 키 `CUKY` · 단위 `UNIT`)가 있어야 뜻이 정해진다 — 통화에 따라 소수점 자리가 다르다 | «`NETWR` 은 `WAERK` 를 참조한다」 | 일반 SAP 지식 |

## E. 확장 · 새 개발 모델
