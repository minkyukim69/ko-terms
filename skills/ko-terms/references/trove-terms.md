## A. 시스템 · 경계

| 용어 | 풀이 |
|---|---|
| 트로브(Trove) | SAP Upgrade · Conversion 을 돕는 **MCP 서버** — 역설계 · 설계 · 개발에 필요한 **SAP 사실**을 MCP API · 연계 API 로 내준다. 산출물은 담지 않는다(chat 이 저장). 영어 *treasure trove*(귀한 것을 모아 둔 곳)에서 왔고 «트로브」 로 읽는다(트로브 CLAUDE.md §1-0) |
| MCP API · 연계 API | 트로브의 두 외부 진입점 — **MCP API**(`/mcp` — LLM 이 대화 중에 tool 을 고른다) · **연계 API**(`/v1` — 소비자의 프로그램 코드가 정해진 순서로 부른다 · 정본 `/v1/openapi.json`). tool 이름 · 응답에 프로젝트 이름을 붙이지 않는다(§1-0) |
| Site · Site Key | 트로브를 쓰는 고객사 · 외부 시스템 단위 · 그 Site 에 발급한 API 키(`trv_` 로 시작 · ID 없이 키 하나로 `/mcp` · `/v1`). 헤더를 못 넣는 MCP 클라이언트는 OAuth(토큰은 Site Key 에 묶임)를 쓴다(§1-1 · architecture §7) |
| 콘솔 | 트로브의 **두 번째 소비자** — 관리(사용자 · Site · Key · 모델 자원 · SAP 접속 · 배치 · 로그 · tool 점검) + 기본 대화(tool 을 대화로 점검 · 산출물 없음)(§1-1) |
| SAP 메타 정보 | 트로브가 저장하는 고객사 관련 정보의 전부 — 미러 스냅샷 · 그래프 · 객체 설명 · 텍스트 오버라이드. 예외로 고객화 해석서를 저장한다(§1-1) |
| 고객화 해석서 | SAP 접속에 딸린 고객화(설정) 해석 문서(요약본 · 상세분석본). «SAP 메타 정보의 확장」 으로 보고 트로브가 저장한다(§1-1 · `docs/config_analysis.md`) |

## B. 적재 · 그래프

| 용어 | 풀이 |
|---|---|
| 적재 | SAP 에서 객체 · 관계를 읽어 트로브의 그래프 · 검색 색인에 넣는 일(적재 표준 IG — `docs/ingest_design.md`) |
| 미러 스냅샷 | 같은 PG 안의 **SAP 접속별 스키마**에 정적 · 구조 테이블(DDIC · config · 텍스트 테이블 등)을 복제해 둔 것(사용 중 스냅샷 `mir_<접속 이름>_full`). 적재 · 배치 코드만 읽는다 — MCP tool · 연계 API 는 읽지 않는다(§0-6) |
| cascade(연쇄 적재) | 한 객체를 적재하면 그것이 가리키는 객체들도 **꼬리를 물고 적재**하는 것 |
| 레인(lane) | 작업을 나눠 **동시에** 도는 줄. 미러 받기의 레인은 그 접속의 SAP 슬롯 상한 안에서 정한다(적재 상세 §2-4). 그래프 적재의 레인은 유형 · 이름 범위로 나눈다(적재 상세 §7-1) |
| slash · `subtype` · 하위유형 · 4-tuple | 객체 유형 표기(예: `TABL/DT` — 구 이름 `adt_slash_type`, 트로브 컬럼 이름 `subtype`) · 같은 유형 안의 세부 구분 · 구 시스템의 식별키 네 개 묶음(sid · object_type · slash · name — 트로브 식별키는 적재 표준 IG7) |
| 게이팅(gating) → **패키지 활성화 점검** | 꺼진 패키지의 객체를 **조회에서 «비활성」 으로 표시하는** 검사(숨기지 않는다 · 적재는 막지 않는다 — 적재 표준 IG12 · 2026-11-02 사용자 결정). «게이팅」 이라고 쓰지 않는다 |
| (게이팅의) OFF closure → **꺼진 패키지와 그 하위 패키지 전체** | «OFF closure」 라고 쓰지 않는다 |
| found | 객체 조회 응답의 있음 표식 — `yes` · `no` · `not_loaded`(SAP 에 있을 수 있으나 적재 전) · `unknown`. «적재 전」 을 «없음」 으로 읽지 않는다(트로브 설계서 §5-4-2) |
