## C. «표」 와 «테이블」 은 다른 말이다 — 한국 IT 현장 관행을 따른다

- **표** = 문서 · 화면의 표(마크다운 표, 화면의 그리드).
- **테이블** = DB 의 table.
- 한국 IT 현장에서는 둘을 **다른 뜻으로 받아들인다.** «표」 를 DB 테이블 뜻으로 쓰면 읽는 사람은 화면의 표로 읽는다.
- 같은 원칙으로, **현장에서 영어 발음 그대로 부르는 말은 그대로 쓴다**(테이블 · 컬럼 · 로우 · 인덱스 · 트랜잭션 · 캐시). 억지로 한국어로 옮기면 아무도 쓰지 않는 방언이 된다.

### D-1. contract 옮기는 법(사용자 확정 2026-11-21)

contract 는 «이렇게 동작하겠다는 약속」 으로 읽는다. 문맥에 따라 계약 · 규약 · 약속 · 명세 중 자연스러운 말을 고른다.

| 쓰이는 곳 | 뜻 | 쓴다 |
|---|---|---|
| Design by Contract(precondition · postcondition · invariant) | 호출하는 쪽과 호출받는 쪽이 각자 지켜야 할 조건 | **계약**(계약에 의한 설계) |
| equals · hashCode contract(Java) | 구현할 때 반드시 지켜야 하는 규칙 | **규약**(Effective Java 한국어판도 이 말을 쓴다) |
| API contract · method contract | 이 함수가 무엇을 받고 무엇을 돌려준다고 보장하는지 | **약속된 동작** · **명세** |
| Interface is a contract | 구현 클래스는 이 메서드들을 반드시 제공해야 함 | **약속** · 풀어서 «반드시 지켜야 할 틀」 |
| Contract testing(Pact 등) | 서비스 사이 API 약속이 깨지지 않았는지 확인하는 테스트 | **계약 테스트** · **컨트랙트 테스트** |
| Data contract | 데이터를 만드는 쪽과 쓰는 쪽이 정한 스키마 · 품질 약속 | **데이터 계약** |
| Smart contract | 블록체인 위에서 자동으로 실행되는 프로그램 | **스마트 컨트랙트**(음차가 일반적) |
| License · service contract | 실제 법적 계약 | **계약** |

- 자주 나오는 자리(예): tool 계약 → **tool 명세**(이름 · 인자 · 응답) · 출력 계약 → **출력 형식**(LLM 이 내야 하는 글의 모양) · 저장 계약 → **저장 API 명세**(저장 요청이 받는 필드).
- 이미 쓴 기록(버전 이력 · 작업 기록 · «옛 …」)은 고치지 않는다.

## E. 풀어 쓰는 IT 용어 — 용어는 그대로 두고 처음 나올 때 풀이

| 용어 | 풀이 |
|---|---|
| MCP · MCP tool | LLM 이 외부 기능을 부르는 **표준 프로토콜** · 그 프로토콜로 내준 **기능 하나**(예: 트로브의 `search_objects`) |
| 벡터 DB · 청크 · 색인 | 문서 조각(청크)의 임베딩 벡터를 저장하고 **뜻이 비슷한 것을 빨리 찾는** 전용 저장소 · 검색 단위로 잘라 낸 문서 조각 · 원본에서 **다시 만들 수 있게** 뽑아 둔 검색용 데이터 |
| 토크나이저 | 글을 모델이 읽는 단위(토큰)로 쪼개는 규칙. 모델마다 다르다 — «512 토큰」 은 그 모델의 토크나이저로 세야 한다 |
| 근사 검색(ANN) · HNSW | 전부 비교하지 않고 **색인을 타고 비슷한 후보를 빨리 찾는** 방식. 빠르지만 가끔 놓친다. HNSW 는 그 색인의 한 종류 |
| BM25 · ts_rank | 낱말 검색의 점수 계산법. **드문 낱말이 맞으면 더 높게** 친다(BM25). ts_rank 는 PG 내장 점수 함수 |
| 홉(hop) | 엣지 하나를 건너는 **한 단계** |
| BFS | 가까운 단계부터 **한 단계씩 넓혀 가며** 찾는 방식(너비 우선 탐색) |
| 재귀 CTE(`WITH RECURSIVE`) | SQL 이 **자기 결과를 다시 입력으로 써서** 단계를 반복하는 문법 |
| 경로 단위 / 노드 단위 | 결과를 **지나간 길마다** 세는가 / **도착한 객체마다 한 번** 세는가 |
| orphan | 주인(연결)이 없어진 채 **남은** 노드 · 작업 |
| liveness | «지금 실제로 살아 돈다」 는 사실(전담 표시와 다르다) |
| 하트비트 | 작업을 맡은 쪽이 살아 있음을 **주기적으로 남기는 시각** — liveness 를 판정하는 재료 |
| probe | 저장된 것이 최신인지 **변경일 하나만 가볍게 확인**하는 조회 |
| SSOT · 정본 | 그 정보의 **단 하나의 공식 출처** |
| 적대 시험 · 적대적 테스트 | **일부러 틀린 입력 · 결함 · 장애 상황을 넣어** 검사가 잡는지 보는 시험(두 레포지토리 CLAUDE.md GR56) |
| 게이트(gate) | GR56 의 **단계 통과 판정**이다. 테스트 자체가 아니다. 테스트를 돌리는 일은 «테스트」, 판정은 «게이트 통과」 로 쓴다(트로브 사용자 확정 2026-10-15) |
| keyset | 마지막으로 읽은 **키 값 다음부터** 읽는 페이지 방식 |
| 사용처 · 피참조 | 어떤 코드를 **가져다 쓰는 쪽** 코드(두 레포지토리 CLAUDE.md GR57 · GR58) |
| 레포지토리(repository) | **git 으로 버전 관리하는 프로젝트 폴더 전체**. «레포지토리에 있다」 = git 에 커밋돼 다른 곳에서 `git clone` · `git pull` 로 받을 수 있다는 뜻(`.gitignore` 로 뺀 것은 로컬 폴더에 있어도 레포지토리에는 없다). 각 레포지토리의 주소는 `chat-terms.md` · `trove-terms.md` |
| 청크 헤더 · 토큰 예산 · 오버랩 | 청크 앞에 붙이는 «문서 제목 > 섹션 경로」 한 줄 · 청크 하나가 쓸 수 있는 최대 토큰 수(헤더 · 특수 토큰 포함) · 앞 청크의 끝 문장을 다음 청크 앞에 다시 넣는 것(트로브 CLAUDE.md §1-6-1) |
| 엔드포인트 · 끝점 | 같은 영어 *endpoint* 가 분야마다 다른 말이 된다 — **웹 · API** 에서는 부르는 주소(`/v1/connections`)라 «엔드포인트」, **그래프 DB** 에서는 엣지가 가리키는 노드라 «끝점」(«끝 노드」). 한 글에 둘이 섞이면 «API 엔드포인트」 · «엣지의 끝점」 처럼 앞에 분야를 붙인다(2026-11-27 사용자 결정 — A1) |
| 의미 기준 분할 · 문장 window | 문장(또는 몇 문장 묶음)마다 임베딩해 **앞뒤 뜻이 갑자기 달라지는 곳**에서 자르는 방식(semantic chunking) · 그때 한 번에 임베딩하는 «문장 하나 + 앞뒤 문장」 |
| 양자화 · int8 · fp32 · F16 · GGUF · ONNX | 모델 가중치를 더 작은 숫자 형식으로 줄이는 것(빠르고 작지만 결과가 조금 달라진다) · 그 숫자 형식들 · llama.cpp 의 모델 파일 형식 · 여러 실행기가 함께 쓰는 모델 형식 |
| llama.cpp · slot · ubatch | CPU · GPU 에서 모델을 돌리는 오픈소스 서버 · 그 서버가 동시에 처리하는 요청 자리 하나 · 한 번에 처리하는 입력 크기(임베딩 입력 하나가 이 안에 들어가야 한다) |
| pgvector · `halfvec` · 반복 탐색 · 전수 비교 | PG 의 벡터 확장 · 16비트 벡터 형식(크기 절반) · 벡터 인덱스 후보가 필터에 걸려 모자라면 더 뽑아 계속 찾는 방식(`hnsw.iterative_scan`) · 인덱스 없이 조건에 맞는 벡터를 모두 비교하는 검색(느리지만 빠뜨리지 않는다) |
| `tsvector` · `pg_trgm` | PG 내장 전문검색용 낱말 목록 형식 · 글자 3개 묶음으로 비슷한 글을 찾는 확장(`ILIKE` 인덱스) |
| advisory lock | PG 의 **이름 붙은 잠금**. 여러 프로세스 중 하나만 어떤 역할을 맡게 할 때 쓴다 |
| `SKIP LOCKED` | 다른 연결이 잡은 로우는 **기다리지 않고 건너뛰는** 조회 옵션 — 작업 큐를 여럿이 나눠 가져갈 때 쓴다 |
| LISTEN/NOTIFY | PG 의 알림 기능. 한 프로세스가 보낸 신호를 다른 프로세스들이 즉시 받는다(캐시 무효화 등) |
| LATERAL | SQL 에서 앞 테이블의 로우마다 뒤 서브쿼리를 그 로우 값으로 다시 도는 JOIN |
| TOAST | PG 가 큰 값(약 2 KB 초과)을 로우 밖 별도 저장소에 나눠 담는 방식 |
| `pg_stat_activity` | PG 가 «각 연결이 지금 무엇을 실행 · 기다리는가」 를 보여 주는 시스템 뷰 |
| `idle_in_transaction_session_timeout` · `statement_timeout` | 트랜잭션을 열어 놓고 놀고 있는 연결을 끊는 설정 · 문장 하나의 실행 시간 상한 |
| PgBouncer · 트랜잭션 모드 | PG 연결 풀러 · 트랜잭션마다 다른 PG 연결을 주는 방식(세션 상태를 남기는 코드가 조용히 깨진다) |
| CONCURRENTLY(인덱스) | 쓰기를 막지 않고 인덱스를 만드는 PG 옵션 — 실패하면 «깨진 인덱스」(`indisvalid=false`)가 남는다 |
| 물리 백업 · 논리 백업 | DB 형식 그대로 통째로(`pg_dump` 커스텀 형식) · 로우를 글 파일로 내보내고 올릴 때 키를 다시 맞춰 넣기 |
| 자연 키 | DB 가 매긴 id 가 아니라 **내용으로 정해지는 키** |
| replica | 같은 컨테이너를 **여러 개 띄운 복제본** — 부하를 나눠 받는다 |
| stateless | 요청과 요청 사이에 **프로세스 메모리에 꼭 필요한 상태를 남기지 않는** 방식 — 어느 replica 가 받아도 결과가 같다 |
| 롤링 업데이트 | 서비스를 멈추지 않고 인스턴스를 하나씩 새 버전으로 바꾸는 배포 방식(쿠버네티스가 파드를 일부러 죽인다) |
| cgroup · CFS quota | 컨테이너에 준 CPU · 메모리 상한 · 쿠버네티스가 CPU 상한을 거는 방식(`cpu.max`) — 코어 수를 `os.cpu_count()` 로 읽으면 틀린다 |
| NAT · SNAT | 출발 · 도착 주소를 바꿔 주는 네트워크 장치 · 출발 주소를 바꾸는 것(여러 사용자가 한 IP 로 합쳐진다 — IP 로 사용자를 가르지 않는 이유) |
| 리버스 프록시 · gateway | 외부 요청을 받아 경로에 따라 뒤 서버로 나눠 보내는 앞단 서버 — TLS(HTTPS) 처리도 한다 |
| BFF | 브라우저와 백엔드 사이의 **UI 서버 쪽 중계 계층**(Backend for Frontend) — 비밀값은 여기서만 다룬다 |
| CSRF 토큰 | 서버가 상태를 바꾸는 요청마다 요구하는 확인값(SAP 은 GET 에 `x-csrf-token: Fetch` 를 실어 받고 같은 연결의 POST 에 다시 싣는다) |
| 커넥션 풀 | 미리 만들어 돌려 쓰는 연결 묶음(DB · HTTP) |
| OAuth · CIMD · DCR | 로그인 화면을 거쳐 짧게 쓰는 토큰을 받아 서버를 부르는 표준 인증 방식 · 클라이언트 id 자체가 https 주소이고 그 주소에 클라이언트 정보가 있는 등록 방식 · 클라이언트가 인증 서버에 스스로 등록하는 방식 |
| 사내 CA · 신뢰 목록 · 사설 인증서 | 회사가 만든 루트 인증서 · 시스템이 믿는 루트 인증서 목록 · 공인 CA 가 아닌 곳에서 발급한 서버 인증서 |
| OSV · GHSA · CVE | 공개 취약점 데이터베이스 · 공개된 취약점의 번호 체계 |
| RCE · SSRF · 서비스 거부(DoS) | 원격 코드 실행 · 서버를 시켜 내부망 주소를 대신 부르게 하는 공격 · 서버를 멈추거나 느리게 만드는 공격 |
| 기준 이미지 | Dockerfile 의 `FROM` 에 적힌, 이미지의 바탕이 되는 이미지 |
| 빌드 캐시 · 댕글링 이미지 · 익명 볼륨 | 도커가 빌드 층을 재사용하려고 남긴 것(`docker builder prune`) · 태그를 잃은 이미지(`<none>`) · 이름 없이 만들어진 볼륨(`rm -v` 없이 컨테이너를 지우면 남는다) |
| Xvfb | 모니터 없는 서버에서 화면이 있는 것처럼 해 주는 가상 화면 |
| Playwright | 브라우저(Chromium)를 코드로 조작하는 라이브러리 — 클릭 · 입력 · 파일 받기 · 화면 캡처 |
| HITL | 사람이 중간에 결정하는 흐름(human in the loop) |
| Mermaid | 글로 그래프 · 흐름도를 적는 문법(트로브 배치 묶음 템플릿의 원본 형식) |
| SSE | 서버가 응답을 조각조각 흘려보내는 HTTP 방식(Server-Sent Events) |
| pre-commit · 가드 | 커밋 직전에 도는 git hook · 그 hook 이 부르는 규칙 검사 스크립트(오탐이면 끄지 않고 규칙을 고친다) |
