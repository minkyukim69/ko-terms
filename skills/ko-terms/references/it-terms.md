## C. «표」 와 «테이블」 은 다른 말이다 — 한국 IT 현장 관행을 따른다

- **표** = 문서 · 화면의 표(마크다운 표, 화면의 그리드).
- **테이블** = DB 의 table.
- 한국 IT 현장에서는 둘을 **다른 뜻으로 받아들인다.** «표」 를 DB 테이블 뜻으로 쓰면 읽는 사람은 화면의 표로 읽는다.
- 같은 원칙으로, **현장에서 영어 발음 그대로 부르는 말은 그대로 쓴다**(테이블 · 컬럼 · 로우 · 인덱스 · 트랜잭션 · 캐시). 억지로 한국어로 옮기면 아무도 쓰지 않는 방언이 된다.

### D-1. contract 옮기는 법(사용자 확정 2026-11-21)

contract 는 «이렇게 동작하겠다는 약속」 으로 읽는다. 문맥에 따라 계약 · 규약 · 약속 · 명세 중 자연스러운 말을 고른다.

| 쓰이는 곳 | 뜻 | 쓴다 |
|---|---|---|
| Design by Contract(precondition · postcondition · invariant) | 호출하는 쪽과 호출받는 쪽이 각자 지켜야 할 조건 | **계약**(계약에 의한 설계) |
| equals · hashCode contract(Java) | 구현할 때 반드시 지켜야 하는 규칙 | **규약**(Effective Java 한국어판도 이 말을 쓴다) |
| API contract · method contract | 이 함수가 무엇을 받고 무엇을 돌려준다고 보장하는지 | **약속된 동작** · **명세** |
| Interface is a contract | 구현 클래스는 이 메서드들을 반드시 제공해야 함 | **약속** · 풀어서 «반드시 지켜야 할 틀」 |
| Contract testing(Pact 등) | 서비스 사이 API 약속이 깨지지 않았는지 확인하는 테스트 | **계약 테스트** · **컨트랙트 테스트** |
| Data contract | 데이터를 만드는 쪽과 쓰는 쪽이 정한 스키마 · 품질 약속 | **데이터 계약** |
| Smart contract | 블록체인 위에서 자동으로 실행되는 프로그램 | **스마트 컨트랙트**(음차가 일반적) |
| License · service contract | 실제 법적 계약 | **계약** |

- 자주 나오는 자리(예): tool 계약 → **tool 명세**(이름 · 인자 · 응답) · 출력 계약 → **출력 형식**(LLM 이 내야 하는 글의 모양) · 저장 계약 → **저장 API 명세**(저장 요청이 받는 필드).
- 이미 쓴 기록(버전 이력 · 작업 기록 · «옛 …」)은 고치지 않는다.

| 용어 | 풀이 |
|---|---|
| MCP · MCP tool | LLM 이 외부 기능을 부르는 **표준 프로토콜** · 그 프로토콜로 내준 **기능 하나**(예: 트로브의 `search_objects`) |
| 벡터 DB · 청크 · 색인 | 문서 조각(청크)의 임베딩 벡터를 저장하고 **뜻이 비슷한 것을 빨리 찾는** 전용 저장소 · 검색 단위로 잘라 낸 문서 조각 · 원본에서 **다시 만들 수 있게** 뽑아 둔 검색용 데이터 |
| 토크나이저 | 글을 모델이 읽는 단위(토큰)로 쪼개는 규칙. 모델마다 다르다 — «512 토큰」 은 그 모델의 토크나이저로 세야 한다 |
| 근사 검색(ANN) · HNSW | 전부 비교하지 않고 **색인을 타고 비슷한 후보를 빨리 찾는** 방식. 빠르지만 가끔 놓친다. HNSW 는 그 색인의 한 종류 |
| BM25 · ts_rank | 낱말 검색의 점수 계산법. **드문 낱말이 맞으면 더 높게** 친다(BM25). ts_rank 는 PG 내장 점수 함수 |
| 홉(hop) | 엣지 하나를 건너는 **한 단계** |
| BFS | 가까운 단계부터 **한 단계씩 넓혀 가며** 찾는 방식(너비 우선 탐색) |
| 재귀 CTE(`WITH RECURSIVE`) | SQL 이 **자기 결과를 다시 입력으로 써서** 단계를 반복하는 문법 |
| 경로 단위 / 노드 단위 | 결과를 **지나간 길마다** 세는가 / **도착한 객체마다 한 번** 세는가 |
| orphan | 주인(연결)이 없어진 채 **남은** 노드 · 작업 |
| liveness | «지금 실제로 살아 돈다」 는 사실(전담 표시와 다르다) |
| 하트비트 | 작업을 맡은 쪽이 살아 있음을 **주기적으로 남기는 시각** — liveness 를 판정하는 재료 |
| probe | 저장된 것이 최신인지 **변경일 하나만 가볍게 확인**하는 조회 |
| SSOT · 정본 | 그 정보의 **단 하나의 공식 출처** |
| 적대 시험 · 적대적 테스트 | **일부러 틀린 입력 · 결함 · 장애 상황을 넣어** 검사가 잡는지 보는 시험(두 레포지토리 CLAUDE.md GR56) |
| 게이트(gate) | GR56 의 **단계 통과 판정**이다. 테스트 자체가 아니다. 테스트를 돌리는 일은 «테스트」, 판정은 «게이트 통과」 로 쓴다(트로브 사용자 확정 2026-10-15) |
| keyset | 마지막으로 읽은 **키 값 다음부터** 읽는 페이지 방식 |
| 사용처 · 피참조 | 어떤 코드를 **가져다 쓰는 쪽** 코드(두 레포지토리 CLAUDE.md GR57 · GR58) |
| 레포지토리(repository) | **git 으로 버전 관리하는 프로젝트 폴더 전체**. «레포지토리에 있다」 = git 에 커밋돼 다른 곳에서 `git clone` · `git pull` 로 받을 수 있다는 뜻(`.gitignore` 로 뺀 것은 로컬 폴더에 있어도 레포지토리에는 없다). 각 레포지토리의 주소는 `chat-terms.md` · `trove-terms.md` |
