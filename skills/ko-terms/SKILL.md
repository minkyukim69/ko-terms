# ko-terms — 한국어로 쓰고, 한국 IT 현장의 말로 쓴다

이 Skill 은 세 가지를 정한다.

1. **무엇을 한국어로 쓰나**(언어 규칙 — 1절).
2. **어떻게 쓰나**(문서 쓰기 규칙 — 2절).
3. **어떤 낱말을 쓰나**(용어 원칙 — 3절 · 4절 · 용어 표는 `references/`).

자동으로 잡을 수 있는 것은 같은 플러그인의 hook `ko_guard` 가 잡는다(6절).
이 Skill 은 chat · 트로브 두 레포지토리가 함께 쓴다. 정본은 플러그인 레포지토리 `ko-terms` 다 — 설치된 사본(플러그인 캐시)을 고치지 않는다(7절).

## 1. 언어 규칙

- 🔴 **반드시 한국어로 쓴다.** 응답 · 질문 · 보고 · 문서 전부다. 긴 작업 뒤의 최종 보고도 예외가 아니다.
- **사용자 눈에 보이는 글은 하나도 빠짐없이 한국어다.** 대상은 넷이다.
  1. 도구 호출 **사이의 짧은 진행 메시지**(«무엇을 하는 중」 한두 줄)
  2. **도구 호출 설명**(명령마다 붙이는 «무엇을 실행하는지」 한 줄)
  3. 최종 보고 · 질문
  4. 커밋 메시지 · 문서 · 시험이 찍는 결과 문구 · 코드 주석 · docstring
- 그대로 두는 것: **코드 · 명령 · 식별자 · 바깥 도구의 출력 원문**뿐이다.
- 하위 에이전트에게 글을 쓰게 하면 **«한국어로 쓴다」 를 지시에 적는다.**
- 영어로 답한 것을 알아채면 **다음 응답을 기다리지 말고 바로 한국어로 다시 쓴다.**
- 작업이 길어질수록(시험 반복 · 백그라운드 대기 · 컨텍스트가 길어질 때) 영어로 미끄러지기 쉽다. **글을 내보내기 전에 한국어인지 한 번 본다.**
- 영어로 써야 할 때는 사용자가 글 앞에 `!en` 을 붙인다. 그 턴만 hook 이 검사하지 않는다. 글 중간의 `!en` 은 효력이 없다.

## 2. 문서 쓰기 규칙 — «처음 보는 사람이 읽을 수 있게」

압축 · 기호 · 약어로 요약하면 쓸 때만 편하고 나중에 아무도 못 읽는다.

1. **한 문장에 한 가지.**
2. 처음 나오는 말은 **바로 옆에서 풀어 준다.**
3. 기호 나열 대신 **«무엇을 하려다 무엇이 됐다」** 는 이야기로 쓴다.
4. 결함은 **하려던 것 → 벌어진 일 → 왜 못 알아챘나 → 어떻게 고쳤나** 순서로 쓴다.
5. 숫자는 **어디서 잰 것인지**를 같이 쓴다.
6. **기술 용어는 한국 개발 현장에서 쓰는 말로** 쓴다(3절 · `it-terms.md`).
7. **레포지토리 밖 파일을 표준 문서에서 참조하지 않는다** — 레포지토리를 받은 사람과 다음 세션은 그 파일을 읽을 수 없다. 필요한 내용은 레포지토리 문서로 옮겨 적는다.

- **상태는 네 낱말로만 적는다**: **정상 동작 / 결함 / 미구현 / 확인 필요**. 비유(«덮는다」 · «열려 있다」)로 상태를 말하면 읽는 사람이 «해결됐다」 인지 «남은 일」 인지 반대로 읽는다.
- **쓴 뒤에 세어 본다.** 문서를 쓰고 나면 «쓰지 않는다」 낱말을 실제로 검색한다. 단 **글자만 보고 고치지 않는다** — 같은 글자가 다른 뜻일 수 있다(«총계정원장」 은 SAP 회계 용어라 무관). 찾는 것은 검색으로, 판정은 읽어서 한다.
- **한꺼번에 바꾸지 않는다** — sed · 정규식으로 일괄 치환하지 않고 한 자리씩 읽어 고친다. 같은 글자가 다른 뜻인 자리를 망가뜨린다.

## 3. 용어 원칙

- **현장에서 영어 발음 그대로 부르는 말은 그대로 쓴다** — 테이블 · 컬럼 · 로우 · 인덱스 · 트랜잭션 · 캐시 · 커밋 · 빌드 · 버전 · 레포지토리 · 엔드포인트 · 프롬프트 · 에이전트. 억지로 한국어로 옮기면 아무도 쓰지 않는 방언이 된다.
- **Version 은 «버전」 이다.** 대화 · 문서 · 화면 모두 그렇다(결정 K4). «판」 이라고 쓰지 않는다.
- **Repository 는 «레포지토리」 다**(결정 K5).
- **통계 · 수학 용어를 그대로 쓰지 않는다.** 틀린 말은 아니지만 현장에서 그렇게 부르지 않아, 읽는 사람이 한 번 더 번역해야 한다(예: 외삽 → «지금 값으로 계산하면」).
- 🔑 판정 질문: *«이 말을 옆자리 개발자에게 소리 내어 했을 때 되묻지 않을까?»* 되물을 것 같으면 풀어서 쓴다.
- **낱말을 줄여 붙이지 않는다** — 다른 낱말이 된다(«표에 한해서만」 을 «표면」 으로 줄이면 surface 로 읽힌다).
- **«얇다」 는 thin layer 뜻으로만 쓴다**(로직 없는 통과 계층). «내용이 적다」 뜻으로는 코드가 쓰는 낱말(`pending` · `confidence='low'`)을 빌리거나 «근거가 부족하다」 로 쓴다.
- **«표」 와 «테이블」 은 다른 말이다.** 표 = 문서 · 화면의 표 / 테이블 = DB 의 table(`it-terms.md` C절).
- **코드 식별자 안의 글자는 바꾸지 않는다** — 함수 · 변수 · 상태값 이름이 코드와 달라지면 찾을 수 없다(예: `pin_run` 은 그대로 · 설명만 «버전 고정」).
- **SAP 이름 · 값은 원문 그대로 쓴다** — 대소문자 · 앞자리 0 · 앞쪽 공백을 바꾸지 않는다(`sap-terms.md`).

## 4. 읽는 사람

- 읽는 사람은 **IT 개발 전문가**다. 데이터 분석 · 수학 · 그래프 이론 · 검색 순위 계산의 전문가는 아니다.
- 그래서 **IT 일반 용어는 풀지 않고**, 그 밖의 분야 용어와 프로젝트가 만든 말은 **바꾸거나 풀어 쓴다.**
- 문서마다 머리에 **«이 문서에 나오는 용어」 표**를 둔다. 아래 참조 파일의 «풀어 쓰는 말」 중 그 문서에 실제로 나오는 것만 싣는다.

## 5. 참조 파일 — 언제 무엇을 읽나

참조 파일은 이 플러그인 안에 있다: `${CLAUDE_PLUGIN_ROOT}/skills/ko-terms/references/`.

| 이럴 때 | 읽는 파일 |
|---|---|
| 영어 IT 용어를 한국어로 옮길 때 · 어떤 낱말을 쓰지 말아야 하는지 볼 때 · «표 · 테이블」 · 통계 용어 · contract 를 옮길 때 | `${CLAUDE_PLUGIN_ROOT}/skills/ko-terms/references/it-terms.md` |
| SAP 용어(SID · client · 객체 유형 · TR · 데이터 요소 · BAdI …)를 쓰거나 풀어 쓸 때 | `${CLAUDE_PLUGIN_ROOT}/skills/ko-terms/references/sap-terms.md` |
| chat 레포지토리에서 일할 때 · chat 이 만든 말(결속 · 용도 · 조견표 · QD 등록 · 사실 장 …)을 쓸 때 | `${CLAUDE_PLUGIN_ROOT}/skills/ko-terms/references/chat-terms.md` |
| 트로브 레포지토리에서 일할 때 · 트로브가 만든 말(적재 · 미러 스냅샷 · 레인 · found …)을 쓸 때 | `${CLAUDE_PLUGIN_ROOT}/skills/ko-terms/references/trove-terms.md` |

- 지금 레포지토리가 어느 쪽인지는 작업 폴더 이름(`chat` · `trove`)과 CLAUDE.md 머리로 안다. 다른 쪽 시스템을 이야기하는 글(chat 에서 트로브를 · 트로브에서 chat 을)이면 두 파일을 함께 본다.
- 자동 검사 규칙의 정본은 `${CLAUDE_PLUGIN_ROOT}/skills/ko-terms/rules.json` 이다(사람이 읽을 일은 드물다 — `it-terms.md` 의 «자동 검사」 칸이 그 규칙 번호를 가리킨다).

## 6. hook `ko_guard` 와의 관계

hook 은 판정만 하고, 고치는 것은 Claude 다. 잡는 것은 다섯 자리다.

| 언제 | 무엇을 | 어떻게 |
|---|---|---|
| 세션 시작 · 이어하기 · 요약 뒤 | 언어 규칙 요약을 넣는다 | 컨텍스트에 추가 |
| Bash 실행 직전 | 도구 호출 설명 · `git commit -m` 첫 줄이 영어 | 거부 — 한국어로 고쳐 다시 부른다 |
| 도구 결과가 돌아온 뒤 | 결과에 영어가 많음 | «다음 글도 한국어로」 한 줄 |
| 답을 끝낼 때 | 답이 한국어가 아님 · 자동 검사 용어(`it-terms.md` 의 T 번호)가 있음 | 한 번 재작성 요청 |
| 하위 에이전트가 보고를 끝낼 때 | 보고가 한국어가 아님 | 한 번 재작성 요청 |

- **재작성 요청을 받으면** 그 사유대로 고친 글을 쓴다. 앞의 글은 이미 화면에 나가 남아 있으므로 «다시 씁니다」 · 사과 없이 고친 글만 쓴다.
- 재작성 요청은 **한 번만** 한다. 두 번째 글은 검사하지 않고 사용자에게 간다.
- 용어 자체를 이야기하는 자리(«판」 을 버전으로 바꾼다 같은 글)는 그 말을 **«…」 로 감싼다.** 인용 안은 검사하지 않는다. 마크다운 표 칸처럼 인용 없이 적으면 hook 이 걸러 내지 못한다.
- 뜻을 읽어야 가를 수 있는 말(예: «배치」 = batch 와 deployment · «저장소」 = storage 와 repository)은 hook 이 보지 않는다 — 이 Skill 의 판단으로 쓴다.

## 7. 고치는 법 — 정본은 플러그인 레포지토리

- 용어를 더하거나 고칠 때는 **플러그인 레포지토리 `ko-terms`** 를 받아(clone · pull) 거기서 고치고 커밋 · push 한다. 설치된 사본(`~/.claude/plugins/cache/…`)은 버전이 바뀌면 사라진다.
- 프로젝트 용어는 그 프로젝트 파일(`chat-terms.md` · `trove-terms.md`)에만 더한다. 두 프로젝트에 공통인 말은 `it-terms.md` · `sap-terms.md` 에 둔다.
- `rules.json` 의 규칙 번호를 더하거나 빼면 `it-terms.md` 의 «자동 검사」 칸을 같은 커밋에서 고치고, 레포지토리의 시험(`tests/`)을 2회 돌린다.
- 받는 쪽은 `claude plugin update ko-terms@ko-terms` 또는 세션에서 `/plugin marketplace update ko-terms` 뒤 `/reload-plugins` 로 새 버전을 받는다.
